# INFO 7375 — Branding and AI

Fall 2026. **Predict → Build It → Use It → Ship It → Verify**.

## Description

Students develop a running brand through audience research, positioning, architecture, identity, voice, touchpoints, campaigns, measurement, governance, and a verified portfolio handoff. They use Claude Code and small Python implementations to make brand decisions inspectable. The creative work matters alongside the mechanism: passing a validator does not establish audience fit or a truthful claim.

## Learning outcomes

- Define an audience, brand promise, evidence, and deliberate exclusions.
- Translate strategy into coherent identity, voice, and experience.
- Implement Python tools for structured briefs, creative specimens, evidence, measurement, and version tracking.
- Distinguish hypotheses, synthetic personas, observed feedback, and unsupported claims.
- Interpret metrics with their denominators, assumptions, and causal limits.
- Design explicit governance and approval conditions.
- Deliver a case study and brand package showing actual human and AI contributions.

## Method and readings

The [fifteen-lesson map](COURSE.md) covers all nineteen core chapters. Each lesson records a prediction, builds a mechanism and brand artifact, applies it with Claude Code, ships a reviewable candidate, and verifies that candidate. Revise and repeat when the evidence changes the decision. [Companion readings](docs/reading-map.md) add targeted skepticism, handoff, and human-responsibility practices.

The book's Ideate, Build, Brand, Ship describes professional work; the five-stage course sequence structures learning and verification. The original book remains available. Madison and broader legacy toolchains are not required by this adaptation. Code is Python; JSON, Markdown, and generated SVG are artifact formats.

Claude Code through NEU is assumed; independent readers need their own Claude Code-enabled account. ## Grading

Lesson Assessments are ungraded. Ten [Assignments](assignments/fall-2026/README.md) occur every ten days with dates in Canvas. Each has implementation 60, Frictional 10, GitHub posting 10, and Relative Quartile 20, totaling 100. Implementation includes the requested creative work and its supporting Python mechanism, not code alone.

Use one running brand throughout the term. A personal or fictional project is acceptable; organizational work requires appropriate authority. Wrong original predictions and unsuccessful attempts are legitimate learning evidence. Frictional is an honest log, not a performance of suffering. No invented interviews, endorsements, approvals, or results.

Submit matching Canvas and GitHub versions under fall-2026/first-name-last-initial/assignment-XX/, with the final commit hash in Canvas. Explain your starting sources and what you changed. Videos and Brutalist are optional, with no separate points. A well-supported written and visual package can earn full credit. A mock launch is sufficient; ad spending and public deployment are not required.

## Reading and practice limits

Archetypes are creative heuristics, not validated diagnoses of people. Name uniqueness in a local inventory does not establish legal rights. Evidence ledgers do not certify sustainability or legal compliance. Cultural fit is not established by model-generated stereotypes. Quantitative classroom examples do not establish market impact. Identify the missing evidence and review needed in each case.
