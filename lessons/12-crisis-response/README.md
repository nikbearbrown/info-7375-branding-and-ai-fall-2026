# Lesson 12 — Respond to what is known, not what sounds reassuring

**Predict → Build It → Use It → Ship It → Verify**

Reading: [Chapter 16](../../chapters/16-crisis-and-reputation-management.md). See the [reading map](../../docs/reading-map.md) for this semester's adaptations. Tools: Claude Code and Python standard library. Prerequisites: previous lessons and the running brand project. Suggested pacing: one class session plus practice; Canvas controls dates.

## Predict

Which reassuring sentence in a draft response would overstate what is currently known? Record the expectation, assumptions, and a possible falsifier in PREDICTIONS.md before reviewing Claude's output. Preserve the first entry when recording later findings.

## Build It

Build a Python incident ledger separating known facts, allegations, unknowns, actions, next update, and authorized spokesperson. Use a fictional incident. Make an initial attempt before asking for a complete solution. Use learning-artifacts/12-crisis-response/ for main.py, test_main.py, inputs, and outputs. The Python check supports the brand decision; it does not make that decision for you.

## Use It

Ask Claude to draft a holding statement, then update it when a new synthetic fact arrives. Preserve the previous version and identify every changed assertion. Record actual prompts, model identifier as displayed, date, commands, and outputs. Label fictional brands, synthetic data, simulated feedback, and mock campaigns. Claude Code is assumed; direct API calls are optional and may consume separate credits.

## Ship It

Deliver incident ledger, two statements, update diff, and decision log. Add README.md with exact reproduction commands, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md from the [templates](../../templates/README.md). Package a local candidate ready for review. The [Assignment map](../../assignments/fall-2026/README.md) specifies final submission.

## Verify

Test an allegation presented as confirmed and a promise without an owner. All messages are draft classroom artifacts; do not contact customers or publish a crisis statement. Check the packaged candidate rather than only the development copy. Record actual results and unresolved limits. If a check fails, revise, ship, and verify again. Compare the outcome with your prediction.

## Irreducibly Human

**AI should** draft and compare statements against the fact record.

**Human should** judge the response, preserve uncertainty, and authorize real commitments.

Record the actual division in CONTRIBUTIONS.md: accepted, changed, rejected, or still uncertain. Do not invent audience feedback, testimonials, approvals, or creative decisions that a person did not make.
