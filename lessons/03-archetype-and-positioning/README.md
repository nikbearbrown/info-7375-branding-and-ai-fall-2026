# Lesson 3 — Turn strategy into a useful constraint

**Predict → Build It → Use It → Ship It → Verify**

Reading: [Chapter 5](../../chapters/05-brand-archetypes-as-a-system.md), [Chapter 6](../../chapters/06-brand-strategy-and-positioning.md). See the [reading map](../../docs/reading-map.md) for this semester's adaptations. Tools: Claude Code and Python standard library. Prerequisites: previous lessons and the running brand project. Suggested pacing: one class session plus practice; Canvas controls dates.

## Predict

Which positioning decision will force you to decline an otherwise attractive feature or message? Record the expectation, assumptions, and a possible falsifier in PREDICTIONS.md before reviewing Claude's output. Preserve the first entry when recording later findings.

## Build It

Build a Python strategy checker for audience, category, benefit, reason to believe, voice principles, and explicit refusals. Use archetypes as optional creative heuristics rather than psychological diagnoses. Make an initial attempt before asking for a complete solution. Use learning-artifacts/03-archetype-and-positioning/ for main.py, test_main.py, inputs, and outputs. The Python check supports the brand decision; it does not make that decision for you.

## Use It

Ask Claude for three positioning alternatives and a counterexample to each. Select one and document why the other two fit less well. Record actual prompts, model identifier as displayed, date, commands, and outputs. Label fictional brands, synthetic data, simulated feedback, and mock campaigns. Claude Code is assumed; direct API calls are optional and may consume separate credits.

## Ship It

Deliver positioning statement, strategy configuration, checker, and rejected alternatives. Add README.md with exact reproduction commands, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md from the [templates](../../templates/README.md). Package a local candidate ready for review. The [Assignment map](../../assignments/fall-2026/README.md) specifies final submission.

## Verify

Test contradictory benefit/constraint pairs and unsupported reasons to believe. A consistent configuration still requires audience evidence. Check the packaged candidate rather than only the development copy. Record actual results and unresolved limits. If a check fails, revise, ship, and verify again. Compare the outcome with your prediction.

### Assessments — ungraded

1. Produce the brand artifact and supporting Python mechanism.
2. Run the specified positive and failure cases and explain one result yourself.
3. Identify a case in which the code passes but the brand claim or decision remains unsupported.

## Irreducibly Human

**AI should** generate and compare strategic alternatives.

**Human should** select and defend the positioning and the tradeoffs it creates.

Record the actual division in CONTRIBUTIONS.md: accepted, changed, rejected, or still uncertain. Do not invent audience feedback, testimonials, approvals, or creative decisions that a person did not make.
