# Lesson 15 — Ship a coherent brand someone else can use

**Predict → Build It → Use It → Ship It → Verify**

Reading: [Chapter 19](../../chapters/19-professional-presence-and-launch.md). See the [reading map](../../docs/reading-map.md) for this semester's adaptations. Tools: Claude Code and Python standard library. Prerequisites: previous lessons and the running brand project. Suggested pacing: one class session plus practice; Canvas controls dates.

## Predict

Will your strategy, creative assets, campaign claims, and portfolio tell the same story in the shipped version? Record the expectation, assumptions, and a possible falsifier in PREDICTIONS.md before reviewing Claude's output. Preserve the first entry when recording later findings.

## Build It

Integrate the Python tools, brand brief, identity, voice, campaign drafts, evidence, and guidelines into one versioned handoff. Add a launch checklist naming approval and rollback conditions. Make an initial attempt before asking for a complete solution. Use learning-artifacts/15-verified-brand-handoff/ for main.py, test_main.py, inputs, and outputs. The Python check supports the brand decision; it does not make that decision for you.

## Use It

Use Claude Code to audit the final package for contradictions and missing evidence. Prepare a mock launch and record unresolved decisions before any real publication. Record actual prompts, model identifier as displayed, date, commands, and outputs. Label fictional brands, synthetic data, simulated feedback, and mock campaigns. Claude Code is assumed; direct API calls are optional and may consume separate credits.

## Ship It

Deliver brand handoff package, runnable Python tools, final case study, verification record, and launch-readiness memo. Add README.md with exact reproduction commands, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md from the [templates](../../templates/README.md). Package a local candidate ready for review. The [Assignment map](../../assignments/fall-2026/README.md) specifies final submission.

## Verify

Reproduce generated assets from declared inputs; inspect the actual renderings; trace one claim end-to-end. Correct inconsistencies and identify the final checked revision. Public deployment is optional and needs authorization. Check the packaged candidate rather than only the development copy. Record actual results and unresolved limits. If a check fails, revise, ship, and verify again. Compare the outcome with your prediction.

### Assessments — ungraded

2. Run the specified positive and failure cases and explain one result yourself.
3. Identify a case in which the code passes but the brand claim or decision remains unsupported.

## Irreducibly Human

**AI should** assemble, check, and challenge the candidate package.

**Human should** set final creative direction, verify the evidence, and own approvals and the handoff.

Record the actual division in CONTRIBUTIONS.md: accepted, changed, rejected, or still uncertain. Do not invent audience feedback, testimonials, approvals, or creative decisions that a person did not make.
