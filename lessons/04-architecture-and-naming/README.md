# Lesson 4 — Give the brand a coherent structure

**Predict → Build It → Use It → Ship It → Verify**

Reading: [Chapter 7](../../chapters/07-brand-architecture-and-portfolio.md), [Chapter 8](../../chapters/08-naming-trademark-and-brand-protection.md). See the [reading map](../../docs/reading-map.md) for this semester's adaptations. Tools: Claude Code and Python standard library. Prerequisites: previous lessons and the running brand project. Suggested pacing: one class session plus practice; Canvas controls dates.

## Predict

Will your product names make the relationship to the parent brand clear? Identify likely ambiguity. Record the expectation, assumptions, and a possible falsifier in PREDICTIONS.md before reviewing Claude's output. Preserve the first entry when recording later findings.

## Build It

Build a Python brand-tree validator and name-candidate ledger. Detect duplicate IDs, cycles, missing parent references, and normalized name collisions within the classroom inventory. Make an initial attempt before asking for a complete solution. Use learning-artifacts/04-architecture-and-naming/ for main.py, test_main.py, inputs, and outputs. The Python check supports the brand decision; it does not make that decision for you.

## Use It

Ask Claude to generate names constrained by your strategy. Compare branded-house and separate-brand structures. Record availability and legal clearance as unverified unless actually established through an appropriate process. Record actual prompts, model identifier as displayed, date, commands, and outputs. Label fictional brands, synthetic data, simulated feedback, and mock campaigns. Claude Code is assumed; direct API calls are optional and may consume separate credits.

## Ship It

Deliver brand tree, candidate names, validation output, and unresolved clearance questions. Add README.md with exact reproduction commands, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md from the [templates](../../templates/README.md). Package a local candidate ready for review. The [Assignment map](../../assignments/fall-2026/README.md) specifies final submission.

## Verify

Test a cycle, missing parent, and duplicate normalized name. Domain availability, classroom uniqueness, and legal rights are different questions; this exercise does not establish trademark clearance. Check the packaged candidate rather than only the development copy. Record actual results and unresolved limits. If a check fails, revise, ship, and verify again. Compare the outcome with your prediction.

### Assessments — ungraded

2. Run the specified positive and failure cases and explain one result yourself.
3. Identify a case in which the code passes but the brand claim or decision remains unsupported.

## Irreducibly Human

**AI should** generate candidates and inspect structural consistency.

**Human should** select the architecture and names and identify unresolved rights or review needs.

Record the actual division in CONTRIBUTIONS.md: accepted, changed, rejected, or still uncertain. Do not invent audience feedback, testimonials, approvals, or creative decisions that a person did not make.
