# Lesson 1 — Make a brand promise you can inspect

**Predict → Build It → Use It → Ship It → Verify**

Reading: [Chapter 1](../../chapters/01-the-creative-engineer.md), [Chapter 2](../../chapters/02-what-a-brand-is-equity.md), [Chapter 3](../../chapters/03-the-ai-toolchain-cowork-codex-madison.md). See the [reading map](../../docs/reading-map.md) for this semester's adaptations. Tools: Claude Code and Python standard library. Prerequisites: basic Python functions, lists, dictionaries, and file reading. Suggested pacing: one class session plus practice; Canvas controls dates.

## Predict

Which promise will distinguish your running brand, and what evidence would make an audience believe it? Record the expectation, assumptions, and a possible falsifier in PREDICTIONS.md before reviewing Claude's output. Preserve the first entry when recording later findings.

## Build It

Build a Python brand-brief validator for audience, problem, promise, evidence, alternatives, exclusions, and owner. Choose a personal, fictional, or authorized organizational brand to carry through the course. Make an initial attempt before asking for a complete solution. Use learning-artifacts/01-brand-as-evidence/ for main.py, test_main.py, inputs, and outputs. The Python check supports the brand decision; it does not make that decision for you.

## Use It

Use Claude Code to draft two competing briefs after your initial prediction. Separate brand assets from claims about audience behavior. Preserve sources and assumptions. Record actual prompts, model identifier as displayed, date, commands, and outputs. Label fictional brands, synthetic data, simulated feedback, and mock campaigns. Claude Code is assumed; direct API calls are optional and may consume separate credits.

## Ship It

Deliver brand-brief.json, validator, two alternatives, and a decision note. Add README.md with exact reproduction commands, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md from the [templates](../../templates/README.md). Package a local candidate ready for review. The [Assignment map](../../assignments/fall-2026/README.md) specifies final submission.

## Verify

Reject missing audience or evidence. Show a structurally complete but unsupported promise. A polished logo or complete schema does not demonstrate brand equity. Check the packaged candidate rather than only the development copy. Record actual results and unresolved limits. If a check fails, revise, ship, and verify again. Compare the outcome with your prediction.

### Assessments — ungraded

1. Produce the brand artifact and supporting Python mechanism.
2. Run the specified positive and failure cases and explain one result yourself.
3. Identify a case in which the code passes but the brand claim or decision remains unsupported.

## Irreducibly Human

**AI should** draft alternatives and flag missing evidence.

**Human should** choose the running project, justify its promise, and own its claims.

Record the actual division in CONTRIBUTIONS.md: accepted, changed, rejected, or still uncertain. Do not invent audience feedback, testimonials, approvals, or creative decisions that a person did not make.
