# Lesson 7 — Check the promise across the journey

**Predict → Build It → Use It → Ship It → Verify**

Reading: [Chapter 11](../../chapters/11-brand-experience-and-touchpoints.md). See the [reading map](../../docs/reading-map.md) for this semester's adaptations. Tools: Claude Code and Python standard library. Prerequisites: previous lessons and the running brand project. Suggested pacing: one class session plus practice; Canvas controls dates.

## Predict

At which touchpoint will the actual experience contradict the brand promise? Name the expected mismatch. Record the expectation, assumptions, and a possible falsifier in PREDICTIONS.md before reviewing Claude's output. Preserve the first entry when recording later findings.

## Build It

Build a Python journey-state simulator for discovery, consideration, use, support, and exit. Record promises, actions, failure paths, and the owner of each handoff. Make an initial attempt before asking for a complete solution. Use learning-artifacts/07-touchpoints-and-experience/ for main.py, test_main.py, inputs, and outputs. The Python check supports the brand decision; it does not make that decision for you.

## Use It

Ask Claude to walk through a fictional customer journey against your prototype. Compare the simulated trace with any actual usability observation you obtain; do not conflate them. Record actual prompts, model identifier as displayed, date, commands, and outputs. Label fictional brands, synthetic data, simulated feedback, and mock campaigns. Claude Code is assumed; direct API calls are optional and may consume separate credits.

## Ship It

Deliver journey map, simulator, failure trace, and repair proposal. Add README.md with exact reproduction commands, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md from the [templates](../../templates/README.md). Package a local candidate ready for review. The [Assignment map](../../assignments/fall-2026/README.md) specifies final submission.

## Verify

Test an unsupported transition, a dead end, and an unresolved support handoff. A simulated customer is not a real customer testimonial. Check the packaged candidate rather than only the development copy. Record actual results and unresolved limits. If a check fails, revise, ship, and verify again. Compare the outcome with your prediction.

3. Identify a case in which the code passes but the brand claim or decision remains unsupported.

## Irreducibly Human

**AI should** simulate paths and propose failure cases.

**Human should** inspect the experience, gather real feedback when available, and own service commitments.

Record the actual division in CONTRIBUTIONS.md: accepted, changed, rejected, or still uncertain. Do not invent audience feedback, testimonials, approvals, or creative decisions that a person did not make.
