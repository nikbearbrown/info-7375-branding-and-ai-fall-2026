# Lesson 11 — Make the ethical claim earn its evidence

**Predict → Build It → Use It → Ship It → Verify**

Reading: [Chapter 15](../../chapters/15-brand-ethics-purpose-and-sustainability.md). See the [reading map](../../docs/reading-map.md) for this semester's adaptations. Tools: Claude Code and Python standard library. Prerequisites: previous lessons and the running brand project. Suggested pacing: one class session plus practice; Canvas controls dates.

## Predict

Which values or sustainability claim in your draft is least well supported? Predict the qualification it needs. Record the expectation, assumptions, and a possible falsifier in PREDICTIONS.md before reviewing Claude's output. Preserve the first entry when recording later findings.

## Build It

Build a Python claim-proof ledger recording exact wording, scope, evidence, date, limitations, and review status. Use a fictional case or sources you can inspect. Make an initial attempt before asking for a complete solution. Use learning-artifacts/11-purpose-and-proof/ for main.py, test_main.py, inputs, and outputs. The Python check supports the brand decision; it does not make that decision for you.

## Use It

Ask Claude to challenge the scope of each purpose claim. Rewrite unsupported language or mark the claim unusable pending evidence. Treat legal and certification questions as unresolved unless appropriately reviewed. Record actual prompts, model identifier as displayed, date, commands, and outputs. Label fictional brands, synthetic data, simulated feedback, and mock campaigns. Claude Code is assumed; direct API calls are optional and may consume separate credits.

## Ship It

Deliver claim-proof map, revised copy, checker, and limitations. Add README.md with exact reproduction commands, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md from the [templates](../../templates/README.md). Package a local candidate ready for review. The [Assignment map](../../assignments/fall-2026/README.md) specifies final submission.

## Verify

Test evidence for a narrow product being used to support a whole-company claim. A nonempty source field is not proof. The exercise does not certify legal compliance or sustainability. Check the packaged candidate rather than only the development copy. Record actual results and unresolved limits. If a check fails, revise, ship, and verify again. Compare the outcome with your prediction.

### Assessments — ungraded

1. Produce the brand artifact and supporting Python mechanism.
2. Run the specified positive and failure cases and explain one result yourself.
3. Identify a case in which the code passes but the brand claim or decision remains unsupported.

## Irreducibly Human

**AI should** locate candidate support and propose qualified wording.

**Human should** inspect the evidence, decide which claims are defensible, and own the commitments.

Record the actual division in CONTRIBUTIONS.md: accepted, changed, rejected, or still uncertain. Do not invent audience feedback, testimonials, approvals, or creative decisions that a person did not make.
